# 신용등급 하락 미조치 시나리오

## 개요
투자대상 신용등급이 2단계 이상 하락한 후 7일 내 매도 거래를 실행하지 않은 경우를 탐지합니다.

**탐지 목표**: SCN_RATING01 (신용등급 하락 미조치)

**탐지 플로우**: 신용등급 하락 이벤트 → 센서 필터링 (2단계 이상) → 7일 내 매도 거래 ABSENCE 체크 → Scenario

**특징**: AGGREGATE 탐지, ABSENCE_WITHIN 연산, 시간 윈도우 7일, customer_id + security_id 조합 group_key

---

## 실행 순서 (총 13건)
1. DS_SEC - 증권 정보 등록 (3건)
2. DS_HOLD - 고객 보유 현황 등록 (4건)
3. DS_RATING - 신용등급 변경 (4건) ← customer_id 포함
4. DS_TRADE - 매도 거래 (2건)

## 핵심 변경사항 요약

### 🔄 주요 변경 내용

1. **DS_RATING 데이터에 customer_id 추가**
   - 기존: security_id만 포함 (증권 중심)
   - 변경: customer_id + security_id 포함 (고객별 보유 증권 중심)
   - 보유 고객별로 이벤트 생성 (SK하이닉스 보유자 2명 → 2개 이벤트)

2. **group_by_fields 변경**
   - 기존: `['customer_id']`
   - 변경: `['customer_id', 'security_id']`
   - group_key: `CUS_001|KR7000660001` 형식

3. **AGG_NOSELL에 매도 조건 추가**
   - 기존: where_json = null
   - 변경: `{"operator": "AND", "conditions": [{"field": "trade_type", "op": "=", "value": "SELL"}]}`
   - ABSENCE_WITHIN이 "매도 거래 부재"를 정확히 탐지

### 📊 탐지 로직

```
1. DS_RATING 이벤트 발생
   - customer_id: CUS_001
   - security_id: KR7000660001
   - rating_change_level: -3
   ↓
2. event_stream_groups 생성
   - aggregate_id: R_RATING_2LV
   - group_key: CUS_001|KR7000660001
   ↓
3. R_RATING_2LV 센서 평가
   - rating_change_level <= -2 체크
   - group_key: CUS_001|KR7000660001로 탐지
   ↓
4. AGG_NOSELL 룰 평가
   - 같은 group_key (CUS_001|KR7000660001)로
   - 7일 내 trade_type=SELL 이벤트 확인
   - ABSENCE (없으면) → 탐지!
   ↓
5. SCN_RATING01 시나리오 탐지
   - group_key: CUS_001|KR7000660001
   - risk_level: HIGH
```

## 검증 SQL

### 1. 신용등급 변경 이벤트 확인 (customer_id 포함)
```sql
SELECT
  event_stream_id,
  event_data->>'customer_id' as customer_id,
  event_data->>'security_id' as security_id,
  event_data->>'security_name' as security_name,
  event_data->>'previous_rating' as previous_rating,
  event_data->>'current_rating' as current_rating,
  (event_data->>'rating_change_level')::integer as change_level,
  event_dt
FROM event_stream es
LEFT JOIN mapped_storages ms ON es.mapped_storage_id = ms.mapped_storage_id
LEFT JOIN exec_ds_mp edm ON ms.exec_ds_mp_id = edm.exec_ds_mp_id
WHERE edm.data_source_id = 'DS_RATING'
  AND event_dt >= '2025-12-25'
ORDER BY event_dt;
```

**예상**: 4건의 등급 변경 이벤트 (customer_id 포함)

### 2. event_stream_groups 확인
```sql
SELECT
  esg.event_stream_id,
  esg.aggregate_id,
  esg.group_key,
  es.event_dt
FROM event_stream_groups esg
INNER JOIN event_stream es ON esg.event_stream_id = es.event_stream_id
WHERE esg.aggregate_id IN ('R_RATING_2LV', 'AGG_NOSELL')
ORDER BY esg.aggregate_id, esg.group_key;
```

**예상**: R_RATING_2LV와 AGG_NOSELL 모두 4개 그룹 키 생성
- CUS_001|KR7005930003
- CUS_001|KR7000660001
- CUS_002|KR7066570003
- CUS_003|KR7000660001

### 3. 등급 하락 센서 탐지 확인
```sql
SELECT
  sensor_id,
  group_key,
  event_dt,
  detect_dt,
  pass
FROM detect_sensors
WHERE sensor_id = 'R_RATING_2LV'
  AND event_dt >= '2025-12-25'
ORDER BY group_key;
```

**예상**: 3건 탐지 (rating_change_level <= -2)
- CUS_001|KR7000660001 (pass=true, -3단계)
- CUS_002|KR7066570003 (pass=true, -2단계)
- CUS_003|KR7000660001 (pass=true, -3단계)

### 4. 룰 탐지 확인 (7일 내 매도 미실행)
```sql
SELECT
  rule_id,
  group_key,
  operator,
  matched_count,
  pass,
  detected_dt
FROM detect_rules
WHERE rule_id = 'AGG_NOSELL'
  AND detected_dt >= '2025-12-25'
ORDER BY group_key;
```

**예상**: 2건 탐지
- CUS_001|KR7000660001 (matched_count=0, pass=true) → 매도 없음
- CUS_003|KR7000660001 (matched_count=0, pass=true) → 매도 없음

**탐지 안됨**: CUS_002|KR7066570003 (매도 거래 있음, matched_count=1, pass=false)

### 5. 시나리오 탐지 확인
```sql
SELECT
  scenario_id,
  group_key,
  risk_level,
  detected_dt
FROM detect_scenarios
WHERE scenario_id = 'SCN_RATING01'
  AND detected_dt >= '2025-12-25'
ORDER BY group_key;
```

**예상**: 2건 탐지 (risk_level: HIGH)
- CUS_001|KR7000660001
- CUS_003|KR7000660001
