## 단계별 상세 설명

### 1단계: 직원 HR 등록 (DS_EMPLOYEE)

**예상**: EMPLOYEE 엔티티 3개 생성

### 2단계: 직원 계좌 등록 (DS_EMP_ACC)

**예상**:
- EMPLOYEE 엔티티 속성 보강
- EMPLOYEE-OWNS→ACCOUNT 6건 (EMP001: 3개, EMP002: 2개, EMP003: 1개)
- EMPLOYEE-FAMILY_ACCOUNT→ACCOUNT 3건 (EMP001: 2개, EMP002: 1개)
- ACCOUNT Shell 엔티티 9개 생성

### 3단계: 고객 계좌 등록 (DS_CUST_ACC)

**예상**:
- CUSTOMER 엔티티 2개 생성
- CUSTOMER-OWNS→ACCOUNT 2건
- ACCOUNT Shell 엔티티 2개 생성

### 4단계: 이체 거래 (DS_XFER_APPR)

**파생 필드**:
- `is_customer_sender`: sender_account가 customer_id 소유 계좌인지
- `is_employee_family_receiver`: receiver_account가 approver_id 가족 계좌인지

**예상**:
- 두 거래 모두 `is_customer_sender=false`, `is_employee_family_receiver=false`
- S_EMP_FAM_AC 시나리오 탐지 (group_key: EMP001)

## 검증 SQL

### 1단계 검증
```sql
SELECT entity_type, entity_id, attributes->>'emp_name', attributes->>'dept_name'
FROM entity_attributes
WHERE entity_type = 'EMPLOYEE'
ORDER BY entity_id;
```

**예상**: EMP001, EMP002, EMP003 생성

### 2단계 검증
```sql
-- 속성 확인
SELECT entity_id, attributes->'owned_accounts', attributes->'family_accounts'
FROM entity_attributes
WHERE entity_type = 'EMPLOYEE'
ORDER BY entity_id;
```

**예상**: EMP001(3개 owned, 2개 family), EMP002(2개 owned, 1개 family), EMP003(1개 owned)

### 3단계 검증
```sql
SELECT from_entity_id, relation_type, to_entity_id
FROM entity_relations
WHERE from_entity_type = 'CUSTOMER';
```

### 4단계 검증
```sql
-- 탐지 확인
SELECT scenario_id, group_key, detected_at, risk_level
FROM detect_scenarios
WHERE scenario_id = 'S_EMP_FAM_AC';
```
