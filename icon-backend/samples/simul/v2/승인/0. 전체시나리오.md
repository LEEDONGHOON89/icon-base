# 승인 관련 통합 시나리오

## 개요
이체승인 관련 이상행위 탐지 시나리오를 통합하여 실행할 수 있습니다.

**탐지 목표**:
- S_PROXY_APPR (대리승인 이상행위): 1건
- S_URGENT_APPR (긴급승인 이상행위): 1건
- SCN_SELF_APPR (자가승인 이상행위): 1건

---

## 실행 순서 (총 25건)
1. DS_EMPLOYEE - 직원 HR 등록 (7건)
2. DS_XFER_APPR - 이체 거래 (18건)
   - 대리승인 11건
   - 긴급승인 6건
   - 자가승인 1건

## 예상 탐지 결과

### 1. S_PROXY_APPR (대리승인 이상행위)
- 직원 EMP010이 다른 직원에게 대리 승인 요청 (11건)
- login_id와 approver_id가 다른 경우

### 2. S_URGENT_APPR (긴급승인 이상행위)
- 긴급승인 플래그가 설정된 거래 (6건)
- EMP020 → EMP021 긴급승인 패턴

### 3. S_SELF_APPR (자가승인 이상행위)
- XFER_20251215_001: 직원 EMP001이 본인 거래를 본인이 승인
- login_id와 approver_id가 동일한 경우

### 이체 거래 패턴

#### 대리승인 (11건)
- EMP010(박대리)이 다른 직원에게 승인 요청
- 승인자: EMP011(4건), EMP012(3건), EMP013(4건)
- 금액: 30M ~ 70M
- 기간: 2025-12-01 ~ 2025-12-10

#### 긴급승인 (6건)
- EMP020(이긴급) → EMP021(박승인)
- `is_urgent_approval: true` 플래그
- 금액: 20M ~ 50M
- 기간: 2025-12-01 ~ 2025-12-11

#### 자가승인 (1건)
- EMP001이 본인 거래를 본인이 승인
- login_id = approver_id = EMP001
- 금액: 50M

## 시나리오별 집계 매핑

| 시나리오 | 필요 데이터소스 | 탐지 조건 |
|---------|----------------|-----------|
| **S_PROXY_APPR** | DS_EMPLOYEE, DS_XFER_APPR | login_id ≠ approver_id |
| **S_URGENT_APPR** | DS_EMPLOYEE, DS_XFER_APPR | is_urgent_approval = true |
| **S_SELF_APPR** | DS_EMPLOYEE, DS_XFER_APPR | login_id = approver_id |
