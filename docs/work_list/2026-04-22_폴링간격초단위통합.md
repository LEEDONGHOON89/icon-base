# 2026-04-22 폴링 간격 초(seconds) 단위 통합

## 변경일자
2026-04-22

## 변경내용
FILE_SYSTEM_REALTIME / DATABASE 폴링 간격을 에이전트·백엔드 공통 초(seconds) 단위로 통합.
기존에는 에이전트용 `pollIntervalMs`(ms)와 백엔드용 `scanIntervalMinutes`(분) 두 필드가 따로 존재하여 중복·혼란이 있었음.

## 변경상세

### 문제 현황
| 항목 | 문제 |
|---|---|
| UI 라벨 "폴링 간격(초)" | 실제로는 `scanIntervalMinutes` 컬럼에 저장 → **단위가 분(minutes)** 으로 동작 |
| 에이전트 선택 시 `pollIntervalMs` 필드 별도 표시 | 같은 개념이 두 개 필드로 노출 → 사용자 혼란 |
| 값 `1` 입력 → 실제 1분 폴링 | 사용자는 1초로 인식하나 1분으로 동작 |

### 해결 방향
- 단일 "폴링 간격 (초)" 입력 필드 유지
- `scanIntervalMinutes` 컬럼을 FILE_SYSTEM_REALTIME에 한해 **초(seconds) 단위로 재해석**
- 저장 시 `pollIntervalMs = seconds × 1000` 자동 계산 → 에이전트/백엔드 양쪽 동시 반영

### 1. FileSystemRealtimeCollector.java (icon-engine)
**파일**: `icon-backend/icon-engine/.../realtime/FileSystemRealtimeCollector.java`

- `DEFAULT_SCAN_INTERVAL_MINUTES = 1` → `DEFAULT_SCAN_INTERVAL_SECONDS = 60`
- 변환식: `intervalMinutes * 60 * 1000L` → `intervalSeconds * 1_000L`
- 메서드명: `loadScanIntervalMinutes()` → `loadScanIntervalSeconds()`
- 로그: "간격={}분" → "간격={}초"

### 2. AgentSnapshotService.java (icon-api)
**파일**: `icon-backend/icon-api/.../service/AgentSnapshotService.java`

- fallback 변환식: `scanIntervalMinutes * 60_000L` → `scanIntervalMinutes * 1_000L`
- `pollIntervalMs`가 명시되지 않은 경우 `scanIntervalMinutes`(초) × 1000 = ms 계산

### 3. ConfigForm.tsx (icon-frontend)
**파일**: `icon-frontend/src/components/datasource/ConfigForm.tsx`

#### FILE_SYSTEM_REALTIME
- `useEffect` 로드: `pollIntervalMs / 1000` 우선 → `scanIntervalMinutes` 폴백 → 기본값 60초
- "기본 설정" → "폴링 간격 (초)" 필드 플레이스홀더: "기본값: 60초 (1분)"
- 저장 시: `pollIntervalMs = scanIntervalMinutes × 1000` 자동 계산 포함
- "에이전트 수집 설정" 섹션에서 `pollIntervalMs` 별도 입력 제거
  - 남은 항목: 폴 당 최대 처리 라인 수, 최대 레코드 크기

#### DATABASE
- "적재 설정" 섹션에 "폴링 간격 (초)" 추가 (항상 표시, 초↔ms 변환)
- "에이전트 연결" 섹션에서 `pollIntervalMs` 별도 입력 제거
- 에이전트 섹션에는 정보 안내 배너 + "최대 레코드 크기" 만 유지

## 기존 데이터 호환성
- `scan_interval_minutes` 컬럼값이 `1`(기존 1분)이면 이제 1초로 동작 → **저장된 설정 재확인 필요**
- `pollIntervalMs`가 명시된 레코드는 해당 값을 그대로 사용하므로 영향 없음
