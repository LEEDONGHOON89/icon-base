# 2026-04-21 작업 이력 — AgentId 중복 방지 (방안1 + 방안2)

## 배경

config.yaml의 agentId를 수동 관리하면 여러 에이전트가 같은 ID로 연결 시
기존 세션이 강제 종료되거나 수집기가 잘못된 에이전트에 배달되는 문제가 있었음.

## 변경 요약

| 항목 | 내용 |
|---|---|
| 방안1: UUID 자동 영속화 | config.yaml agentId 미설정 시 `data/agent.id` 에서 읽거나 UUID 신규 생성 |
| 방안2: 서버 중복 거부 | 동일 agentId 활성 세션 존재 시 HANDSHAKE_NACK 반환 후 신규 연결 종료 |

## AgentId 결정 우선순위 (방안1)

```
1. config.yaml의 agentId 명시 → 그대로 사용
2. data/agent.id 파일 존재   → 영속화된 ID 재사용
3. 둘 다 없음               → "agent-{12자리 hex}" 신규 생성 후 data/agent.id 저장
```

## 중복 연결 흐름 (방안2)

```
신규 에이전트(중복 agentId) → HANDSHAKE →
  서버: countByAgentIdAndStatus > 0 → DuplicateAgentIdException →
  서버: HANDSHAKE_NACK 전송 + WebSocket 종료 (POLICY_VIOLATION) →
  에이전트: running=false (재연결 중단) + ERROR 로그
```
